# swagger-rust

Generate typed Rust API clients from OpenAPI 3.0/3.1 and Swagger 2.0 documents: serde models, one async function per endpoint, and, for [GPUI](https://www.gpui.rs) apps, cached queries in the spirit of React Query.

It is the Rust counterpart of [swagger-typescript](https://github.com/hosseinmd/swagger-typescript), and reads the same config keys.

- **No runtime crate.** The output is plain Rust that depends only on `serde` and `serde_json` (plus `gpui` and `futures` for the GPUI layer), so it compiles against whichever GPUI your app pins.
- **Any HTTP client.** Requests go through a two-type `Transport` trait. GPUI's `cx.http_client()` implements it; for anything else it is about fifteen lines.
- **Strict or lenient decoding.** Plain serde derives, or tolerant decoding for backends whose JSON drifts from the schema (numbers as strings, `[]` for `{}`, unknown enum values).
- **Readable output.** Formatted with rustfmt, documented from the spec, warning-free under `clippy::pedantic`. Unchanged files are left alone, so builds stay incremental.

## Install

```sh
cargo install swagger-rust
```

## Quick start

```sh
swagger-rust init          # writes swagger-rust.json
# set "url" and "dir", then:
swagger-rust
```

```jsonc
// swagger-rust.json
[
  {
    "url": "https://petstore3.swagger.io/api/v3/openapi.json",
    "dir": "./src/api/petstore",
    "decode": "strict",
    "gpui": false
  }
]
```

The output directory is a module. Declare it in its parent (`mod petstore;` in `src/api/mod.rs`) and add the dependencies:

```toml
[dependencies]
serde = { version = "1", features = ["derive"] }
serde_json = "1"
futures = "0.3"   # only with "gpui": true
```

Then call an endpoint with any `Transport`:

```rust
use api::petstore::{apis, models};

let pet: models::Pet = apis::get_pet_pet_id(&transport, 42).await?;
```

## What gets generated

| File | Regenerated | Contents |
|---|---|---|
| `mod.rs` | yes | the module list |
| `apis.rs` | yes | one `async fn` per endpoint |
| `models.rs` | yes | structs, enums, unions, aliases |
| `runtime.rs` | yes | `Transport`, `HttpRequest`/`HttpResponse`, `ApiError`, query string and multipart encoding |
| `json.rs` | yes | decoding (strict or lenient) |
| `config.rs` | **once** | base url, headers, auth, timeout, response envelope. **Yours to edit**, never overwritten |
| `query_client.rs` | yes, with `gpui` | the GPUI transport and query cache |
| `queries.rs` | yes, with `gpui` | a cached query per GET endpoint |

Every regenerated file starts with `// @generated by swagger-rust`. Generated files a config no longer produces (say, `queries.rs` after turning `gpui` off) are deleted.

### Endpoints

```rust
/// `GET /pets`
///
/// List pets
pub async fn get_pets(
    transport: &(impl runtime::Transport + ?Sized),
    query: &models::GetPetsQueryParams,
    headers: &models::GetPetsHeaderParams,
) -> Result<Vec<models::Pet>, runtime::ApiError>
```

Arguments come in swagger-typescript's order: path parameters, `body`, `query` (a `…QueryParams` struct), `headers` (a `…HeaderParams` struct). Query and header structs implement `Default`, so `&Default::default()` works when you don't need any.

Request bodies can be JSON, `application/x-www-form-urlencoded`, `multipart/form-data` (file fields are `runtime::FilePart`), text or bytes. Responses decode as JSON, `String` (text), `Vec<u8>` (binary) or `()` (no content).

`ApiError` is `Request` (a parameter failed to serialize), `Network`, `Http { status, message, body, .. }` or `Decode`. `config::error_message` fills `message` from error bodies.

### `config.rs`

The generated code calls into `config.rs` for every request:

```rust
pub const BASE_URL: &str = "https://api.example.com/v1";
pub const ARRAY_FORMAT: ArrayFormat = ArrayFormat::Repeat; // ids=1&ids=2; Indices gives ids[0]=1 like qs.stringify
pub const TIMEOUT: Option<Duration> = Some(Duration::from_secs(30));

pub fn url(path: &str) -> String { /* BASE_URL + path */ }
pub fn prepare(request: &mut HttpRequest) { /* add auth, app version… */ }
pub fn unwrap_body(body: Value) -> Value { /* unwrap {"status", "data"} envelopes */ }
pub fn error_message(response: &HttpResponse) -> Option<String> { /* "message" of error bodies */ }
```

### Transport

```rust
pub trait Transport: Send + Sync {
    fn send(&self, request: HttpRequest) -> BoxFuture<'static, Result<HttpResponse, TransportError>>;
}
```

It is implemented for `&T`, `Arc<T>` and `Box<T>`, and, with `gpui: true`, for GPUI's `dyn HttpClient`. With reqwest:

```rust
struct Reqwest(reqwest::Client);

impl Transport for Reqwest {
    fn send(&self, r: HttpRequest) -> BoxFuture<'static, Result<HttpResponse, TransportError>> {
        let method = reqwest::Method::from_bytes(r.method.as_str().as_bytes()).unwrap();
        let mut builder = self.0.request(method, &r.url).body(r.body);
        for (name, value) in &r.headers {
            builder = builder.header(name, value);
        }
        if let Some(timeout) = r.timeout {
            builder = builder.timeout(timeout);
        }
        Box::pin(async move {
            let response = builder.send().await.map_err(TransportError::new)?;
            let status = response.status().as_u16();
            let headers = response.headers().iter()
                .map(|(k, v)| (k.to_string(), v.to_str().unwrap_or_default().to_owned()))
                .collect();
            let body = response.bytes().await.map_err(TransportError::new)?.to_vec();
            Ok(HttpResponse { status, headers, body })
        })
    }
}
```

## GPUI

With `"gpui": true` (and `"gpuiCrate": "gpui_kit"` if you use GPUI through a re-export), every GET endpoint also gets a cached query, the counterpart of swagger-typescript's React Query hooks:

```rust
struct PetView {
    pet: Entity<Query<models::Pet>>,
    _observe: Subscription,
}

impl PetView {
    fn new(id: i64, cx: &mut Context<Self>) -> Self {
        let pet = queries::get_pets_pet_id(cx, id);
        let _observe = cx.observe(&pet, |_, _, cx| cx.notify());
        Self { pet, _observe }
    }
}

impl Render for PetView {
    fn render(&mut self, _: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        match self.pet.read(cx).state() {
            QueryState::Loading => div().child("Loading…"),
            QueryState::Error(error) => div().child(error.to_string()),
            QueryState::Success(pet) => div().child(pet.name.clone()),
        }
    }
}
```

- **Fetching** runs on the background executor through `cx.http_client()`. Retryable failures (no response, 408, 429, 5xx) are retried 3 times with backoff.
- **Shared.** The same endpoint with the same parameters returns the same entity and makes one request.
- **Cached.** Data outlives the entities for `cache_time` (5 min). A view that comes back shows it at once, while it refreshes if older than `stale_time` (default 0).
- **Invalidation.** After a change, `query_client::invalidate_endpoint(cx, queries::GET_PETS)` refetches every `GET /pets` query in use. `invalidate(cx, |key| …)` takes any filter.
- **Prefetch.** `queries::prefetch_get_pets_pet_id(cx, id)` loads data before a view asks for it.
- **Paging.** Endpoints listed in `useInfiniteQuery` return an `InfiniteQuery<T>`. It requests pages 1, 2, 3… through their `page`/`pageNo`/`pageNumber`/`offset` parameter, with `fetch_next_page` and `has_next_page`. Whether a next page exists is read from the page (`has_next`, `last`, current vs total pages, `total`), or decided by your own `set_has_next_page`.
- **Mutations** are plain `apis` calls. `query_client::request(cx, |http| …)` runs one off the main thread; then invalidate, or `set_query_data`.
- Options: `query_client::set_default_options(cx, QueryOptions { stale_time, cache_time, retry, retry_delay })`, or per query with `set_options`.

Requires a GPUI with async-closure `spawn` (2025 and later) and the `futures` crate. If your GPUI's `HttpRequestExt` has no `timeout`, set `"gpuiHttpTimeout": false`.

## Decoding

**`"decode": "strict"`** (default) derives `serde::Deserialize`. A body that doesn't match the schema is an `ApiError::Decode`.

**`"decode": "lenient"`** is for backends that don't keep to their schema. A value that can't be read costs that field, not the response:

| JSON | Field type | Result |
|---|---|---|
| `"42"` | `i64` | `42` |
| `3`, `"3.5"` | `String`, `f64` | `"3"`, `3.5` |
| `1`, `"true"` | `bool` | `true` |
| `[]` | a struct or map | empty / defaults |
| `null` or missing | a required field | its default |
| `"garbage"` | an optional field | `None` |
| `[1, "x", 2]` | `Vec<i64>` | `[1, 2]` |
| `"new_value"` | an enum | `Unknown("new_value")` |

Lenient models still implement `Deserialize` (through `json::FromJson`), so `serde_json::from_str` works on them.

## Types

| Schema | Rust |
|---|---|
| `string` (any format but binary) | `String` |
| `string`, `format: binary` | `Vec<u8>` response, `FilePart` in multipart |
| `integer` `int32` / other | `i32` / `i64` |
| `number` | `f64` |
| `boolean` | `bool` |
| `array` | `Vec<T>` |
| object with properties | a struct |
| `additionalProperties: {schema}` | `HashMap<String, T>` |
| free-form object | `serde_json::Map<String, Value>` |
| `{}`, several `type`s | `serde_json::Value` |
| `enum` of strings / integers | an enum with an `Unknown(_)` variant for values added later |
| `allOf` | one struct with every part's properties |
| `oneOf` / `anyOf` | an enum: by `discriminator`, else the variant the value fits best |
| `nullable`, `type: [T, "null"]`, `oneOf [T, null]` | `Option<T>` |
| not `required` | `Option<T>` |
| recursive references | boxed |

Component schemas keep their names in `PascalCase` (`pet.Pet` becomes `PetPet`). Only the ones an endpoint reaches are generated. Inline objects and enums take their field's name (`status` becomes `Status`), or the parent-prefixed one (`PetStatus`) if that name is taken by a different type. Identical inline types under the same name are generated once, so a header enum repeated on 80 endpoints is one type.

## Configuration

`swagger-rust.json` holds one entry or an array of them. Paths are relative to the file.

| Key | Default | |
|---|---|---|
| `url` | required | Document url or file, JSON or YAML |
| `dir` | required | Output directory |
| `methodName` | `{method}{path}` | Function names from `{method}`, `{path}`, `{operationId}` |
| `prefix` | | Path prefix (regex) left out of `{path}` |
| `includes` / `excludes` | | Regexes on swagger-typescript style names (`getPetsPetId`) |
| `ignore.headerParams` | | Header parameters left out (set them in `config.rs`) |
| `decode` | `strict` | `strict` or `lenient` |
| `gpui` | `false` | Generate the GPUI layer |
| `gpuiCrate` | `gpui` | The crate path GPUI is used through |
| `gpuiHttpTimeout` | `true` | Use `HttpRequestExt::timeout` |
| `useQuery` | | Non-GET endpoints that also get a query |
| `useInfiniteQuery` | | Paged endpoints |
| `baseUrl` | first server | `BASE_URL` of a new `config.rs` |
| `keepJson` | `false` | Save the document as `dir/swagger.json` |
| `local` | `false` | Generate from that saved document |
| `rustfmt` | `true` | Format the output if rustfmt is installed |

A JSON schema for editor completion is in [`schema/config.json`](schema/config.json).

```sh
swagger-rust --config path/to/swagger-rust.json
swagger-rust --local      # from saved documents, offline
swagger-rust --check      # exit 1 if the generated files are out of date (CI)
```

It can also run from a build script: `swagger_rust::generate(&config, Options::default())`.

## Coming from swagger-typescript

Existing `swagger.config.json` entries work once `language`, `reactHooks` and `prettierPath` are dropped. Names line up: `getPetsPetId` becomes `get_pets_pet_id`, and `useInfiniteQuery`/`useQuery`/`includes`/`excludes` entries match the same endpoints.

| swagger-typescript | swagger-rust |
|---|---|
| `services.ts` | `apis.rs` |
| `types.ts` | `models.rs` |
| `hooks.ts` (`reactHooks`) | `queries.rs` (`gpui`) |
| `config.ts`, `httpRequest.ts` | `config.rs` (editable), `runtime.rs` |
| `useGetX(params)` | `queries::get_x(cx, params)` |
| `useGetX.prefetch` | `queries::prefetch_get_x` |
| `useMutation` hooks | `apis::post_x` + `query_client::invalidate_endpoint` |
| `queryClient.setQueryData` | `query_client::set_query_data` |

Not supported (yet): per-branch `url` lists, SignalR hubs, mocks, cookie parameters (set them in `config.rs`), external `$ref`s (typed `serde_json::Value`), callbacks and webhooks.

## Development

```sh
cargo test --workspace                         # unit tests, snapshot tests, runtime tests
UPDATE_SNAPSHOTS=1 cargo test --test generate  # after changing the output
```

`tests/generate.rs` regenerates the clients in `tests/client` (compiled and tested against a mock transport) and `tests/gpui-client` from `tests/fixtures`, and fails if the committed output differs. `tests/gpui-client` needs a GPUI build, so it is outside the workspace; see its README.
